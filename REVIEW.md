# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health()` / L73 | Always returns `{"status": "ok"}` without actually pinging MongoDB. If the database is down, it still returns 200 instead of 503. | Stop MongoDB and call GET /health — it returns 200 instead of 503. | Added `client.admin.command("ping")` and return 503 on exception. |
| 2 | `create_employee()` / L79 | Uses check-then-insert (`find_one` then `insert_one`). Two concurrent requests with the same `emp_code` can both pass the check and both insert, violating uniqueness. | Send two POST /employees with the same emp_code at the exact same time — both succeed with 201. | Created a unique index on `emp_code` and catch `DuplicateKeyError` from `insert_one` directly, removing the `find_one` check. |
| 3 | `create_employee()` / L82 | `datetime.now()` produces a naive datetime (no timezone). MongoDB stores it, but it's ambiguous — the server's local tz leaks in. | Compare `created_at` on servers in different time zones. | Use `datetime.now(timezone.utc)` for a UTC-aware timestamp. |
| 4 | `create_employee()` / L85 | Returns `created_at` as a raw Python datetime object. The API contract requires epoch milliseconds (integer). | Call POST /employees — the response `created_at` is a datetime string, not an integer. | Convert to epoch ms with `int(dt.timestamp() * 1000)`. |
| 5 | `create_employee()` | No validation on `emp_code` format (must be `EMP` + 4-6 digits), email, name length, department length, or shift format. | Send `emp_code: "XYZ"` — it is accepted. | Added Pydantic field validators for each field. |
| 6 | `create_employee()` | Does not reject `shift_start == shift_end`. | Create an employee with `shift_start: "09:30"` and `shift_end: "09:30"`. | Added an explicit check before insert. |
| 7 | `list_employees()` / L93 | `skip = page * page_size` is wrong. For page 1, it skips the first `page_size` records. Should be `(page - 1) * page_size`. | Call GET /employees?page=1 — the first page of results is skipped. | Changed to `(page - 1) * page_size`. |
| 8 | `list_employees()` / L94 | `count_documents({})` always counts the entire collection, ignoring the department filter. | Call GET /employees?department=Sales — `total` shows the count of all employees, not just Sales. | Changed to `count_documents(query)`. |
| 9 | `list_employees()` / L95 | No `sort` on the cursor. The API spec requires sorting by `emp_code` ascending. | Results come back in insertion order, not alphabetical by emp_code. | Added `.sort("emp_code", ASCENDING)`. |
| 10 | `list_employees()` | `created_at` is returned as a datetime instead of epoch ms. | Response `created_at` is a string, not an integer. | Added `format_employee()` to convert datetimes. |
| 11 | `punch_in()` / L101 | No check for `emp is None`. If the employee doesn't exist, line 113 crashes with a `TypeError` (accessing `None["shift_start"]`). | Punch in with a non-existent emp_code — 500 error instead of 404. | Added `if emp is None: raise HTTPException(404)`. |
| 12 | `punch_in()` / L102 | `datetime.fromtimestamp(ms/1000)` returns a naive datetime in the server's local timezone, not UTC. The attendance date, late calculation, and stored datetime are all wrong if the server isn't in IST. | Run the server on a UTC machine: a 09:28 IST punch-in becomes 09:28 UTC, making the date and late calculation wrong. | Use `datetime.fromtimestamp(ms/1000, tz=timezone.utc)` and convert to IST for date logic. |
| 13 | `punch_in()` / L103 | Attendance date is computed from the naive local timestamp's date. Does not apply R1's overnight-shift rule, so night-shift employees get the wrong date. | Employee with shift 22:00-06:00 punches in at 01:00 IST — date is set to the current day instead of the previous day. | Implemented `determine_attendance_date()` with overnight shift logic. |
| 14 | `punch_in()` / L104 | Check-then-insert race: `find_one` then `insert_one`. Two concurrent punch-ins for the same (emp_code, date) can both succeed. | Two simultaneous requests — both return 201 and two records are created. | Created a unique compound index on `(emp_code, date)` and catch `DuplicateKeyError`. |
| 15 | `punch_in()` / L109 | No validation on `status`. Accepts `ABSENT` and `LEAVE`, which should never be created by punch-in. | Punch in with `status: "ABSENT"` — succeeds. | Added Pydantic validator restricting to PRESENT/WFH/ON_DUTY. |
| 16 | `punch_in()` / L110 | Timestamp is not truncated to whole seconds per R1. Sub-second precision is stored and returned. | Punch in at 09:40:00.900 — the extra 900ms is kept and could affect late calculation. | Applied `.replace(microsecond=0)` after conversion. |
| 17 | `punch_in()` / L119 | Returns `doc["id"] = str(res.inserted_id)`. The API contract never includes an `id` field — `_id` is internal. | Response contains an extra `id` field that shouldn't be there. | Removed the `id` assignment entirely and use `format_attendance_record()`. |
| 18 | `punch_in()` | No validation on `punched_at` — doesn't check if it's a valid epoch ms integer (min 100000000000). Accepts negative numbers, floats, strings. | Send `punched_at: 12345` (seconds, not ms) — accepted and produces a 1970 date. | Added `validate_epoch_ms()` checking type and range. |
| 19 | `compute_late_minutes()` / L35 | Uses `punch_in.replace(hour=h, minute=m)` directly. This only works if `punch_in` is already in IST. But `punch_in` is a naive datetime (or UTC), so the hour/minute replacement produces a shift_start in the wrong timezone. | On a UTC server, a 09:28 IST punch-in (03:58 UTC) replaces to 09:30 UTC, giving 0 minutes diff instead of the correct 0 minutes diff in IST. | Convert `punch_in` to IST first, then build `shift_start` in IST for comparison. |
| 20 | `compute_work_hours()` / L41 | Uses Python `round()`, which is banker's rounding (rounds to even). R4 requires half-up rounding. | `round(8.125, 2)` returns `8.12` (banker's), but the correct answer is `8.13`. | Used `Decimal.quantize(ROUND_HALF_UP)`. |
| 21 | `compute_overtime()` / L47 | Returns any positive overtime value. R3 says overtime is counted only when >= 30 minutes; otherwise 0. | 20 minutes of overtime: starter returns 20, correct answer is 0. | Added the `>= 30` threshold check. |
| 22 | `compute_overtime()` / L46 | For overnight shifts, shift_end is the next calendar day, but the code builds shift_end on the attendance date. The calculation is off by 24 hours. | Overnight shift (22:00-06:00) with punch-out at 06:40 IST next day: overtime is hugely wrong. | Added overnight shift detection to place shift_end on `att_date + 1`. |
| 23 | `list_attendance()` / L144 | Loads the **entire filtered result** into memory with `list(db.attendance_logs.find(q))`, then sorts and slices in Python. With 100k records this is slow and uses excessive memory. | With 100k records, the response takes several seconds and consumes hundreds of MB of RAM. | Use database-side `.sort().skip().limit()` so MongoDB handles pagination. |
| 24 | `list_attendance()` / L145 | Only sorts by `date` descending. The contract requires secondary sort by `emp_code` ascending. | Two records on the same date appear in arbitrary order. | Added `.sort([("date", DESCENDING), ("emp_code", ASCENDING)])`. |
| 25 | `list_attendance()` / L149 | Renames `_id` to `id` and includes it in the response. The API contract has no `id` field. | Response includes an `id` field with a MongoDB ObjectId string. | Excluded `_id` from the query with `{"_id": 0}` and use `format_attendance_record()`. |
| 26 | No indexes | No indexes are created at startup. The spec says "create all indexes at startup, idempotently." | The explain endpoint shows COLLSCAN instead of IXSCAN. All queries do full collection scans. | Added `create_indexes()` on startup with all needed indexes. |
| 27 | `list_employees()` / `list_attendance()` | No validation on `page_size` max (100) or `page` min (1). | Send `page_size=999` — returns up to 999 results per page. | Used `Query(20, ge=1, le=100)` for page_size and `Query(1, ge=1)` for page. |

## Not a defect

- **IST as `timezone(timedelta(hours=5, minutes=30))`**: This is correct — IST is a fixed UTC+05:30 offset with no DST, so a fixed `timezone` is appropriate.
- **Using `load_dotenv()` at module level**: Acceptable for this assignment since `.env` values should be overridden by real environment variables.
- **`MongoClient` at module level**: Standard practice for a single-file FastAPI app.
